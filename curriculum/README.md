# Intro-CS curriculum corpus

An author-ready curriculum content corpus covering Python intro-CS concepts through tested reference programs and controlled misconception programs; it is content rather than a build-test fixture.

## Using an activity

Import an activity.json through the Activity Builder JSON workflow, inspect it in Preview, and export SCORM from the builder header; see ../README.md#workflow.

The WA audience mapping is intentionally bounded: WA audience alignment is concept-level to the SCSA Computer Science ATAR (AECSC); unit-level syllabus outcomes are not reproduced.

## Authoring caveats

Every caveat below is copied verbatim from `manifest.json`.

### AST patterns

- **`caveat.ast-pattern-identifier-wildcards`** — AST `_`/`_name` wildcards apply to function/class names, import alias names, argument names, and attribute names; Global.names and keyword argument names remain exact.
- **`caveat.ast-pattern-any-params-stub`** — A trailing `...` in a function pattern such as `def f(a, ...):` matches the written positional prefix and leaves the remaining signature unconstrained.

### Prompt handling

- **`caveat.prompts-not-in-output`** — input() prompts are recorded in the prompt log and console stream, never in the stdout transcript checked by output_assertion.
- **`caveat.strict-prompt-counts`** — With strict_prompt_inputs enabled, every configured input must be consumed and every input() call must have a configured response.

### Values and functions

- **`caveat.function-calls-positional-only`** — function_state return_assertion.arguments call the target function positionally; keyword-argument calls are not supported.
- **`caveat.equals-python-types`** — equals is type-aware: bool does not equal int, integers and floats compare numerically, sequences compare positionally, and dictionaries require identical key sets with recursively equal values.
- **`caveat.random-seed`** — The random seed is deterministic for an identical source and input list, but code or prompt edits change the seed; avoid asserting exact random output across source variants.
- **`caveat.async-function-state`** — function_state return assertions invoke synchronous functions; async functions produce an error result instead of being awaited.
- **`caveat.function-state-error-type-name`** — A function_state expected_error_type passes only when the configured call raises an exception with that exact type name; it does not compare the message or subclass relationship.

### Files and CSV

- **`caveat.csv-boolean-spellings`** — CSV boolean cells accept only True, False, true, or false. Other spellings, including TRUE, 1, and yes, are strings and do not satisfy a bool type assertion.
- **`caveat.binary-exists-only`** — file_state format binary can assert file existence only; content and byte-level comparisons are not exposed.
- **`caveat.workspace-relative-paths`** — Workspace files are addressed by relative paths such as `names.txt`; absolute paths and parent traversal are not valid activity paths.
- **`caveat.content-assertion-single-match-mode`** — A file content_assertion has one match_mode; use an anchored regex when the whole file shape matters while required fragments must be present.
- **`caveat.csv-row-count-includes-header`** — file_state CSV row_count counts the header row as well as data rows.
- **`caveat.seeded-module-imports`** — Student-authored Python modules must be seeded in the workspace and imported by module name from the current workspace directory.

### Budgets and imports

- **`caveat.stdlib-omissions`** — The bundled stdlib omits ctypes, doctest, imaplib, mailbox, multiprocessing, optparse, pdb, pickletools, poplib, pydoc, smtplib, tarfile, unittest, wsgiref, xmlrpc, and _pyrepl (ImportError). asyncio and concurrent remain available.
- **`caveat.forbidden-imports`** — Imports of pyodide, js, _pyodide_base, pyodide_http, socket, ssl, urllib, http, requests, httpx, aiohttp, subprocess, multiprocessing, ctypes, and webbrowser are rejected by the harness.
- **`caveat.watchdog-budgets`** — Python soft budgets are 3 seconds in Check and 15 seconds in Run; JavaScript deadlines are 5 seconds in Check and 20 seconds of silence in Run. The recursion limit is 500.
- **`caveat.value-and-workspace-caps`** — Captured strings and file text are capped at 100,000 characters; captured lists, tuples, and dictionaries at 1,000 items; fallback repr at 500 characters; workspace snapshots at 100 files; output at 1,000,000 characters.

## Gap analysis

The following authoring gaps and alternatives are declared in `manifest.json`.

| Concept | Reason | Author alternative |
| --- | --- | --- |
| networking and sockets | Network access is out of scope by policy; Pyodide activities have no network access. | Seed input files with python_setup.files and assess parsing or transformation locally. |
| GUI, turtle, and pygame programming | The browser runtime has no desktop GUI or graphics event loop for these libraries. | Assess coordinate or rendering logic through returned data and textual output. |
| threads and multiprocessing | multiprocessing is omitted and forbidden, and the activity contract does not provide thread scheduling assertions. | Teach concurrency concepts with diagrams or deterministic sequential simulations. |
| timing and asymptotic complexity measurement | There are no timing assertions; wall-clock measurements are noisy and budget-limited. | Use code_structure min_count checks for required loop or recursion constructs. |
| unit-test frameworks | unittest is stripped from the bundled runtime and pytest is not bundled. | Use activity test_cases as the grading suite and assert student-visible behavior directly. |
| object instance state introspection | The capture API exposes variables, functions, calls, and files, not arbitrary object attributes. | Check constructor and method behavior through function calls and captured output. |
| keyword-argument function calls in function_state | function_state return_assertion.arguments supplies positional arguments only. | Use positional parameter order for return checks and separately assert parameter names/count. |
| exact random output | The seed changes when source or prompt inputs change, so exact outputs are not stable across student edits. | Assert a range, type, or statistical invariant rather than one random sequence. |
| large datasets | Captured strings, sequences, output, and workspace snapshots have explicit size caps. | Use small deterministic fixtures that exercise the same parsing and aggregation logic. |
| database file-content assertions | sqlite3 can import, but file_state only asserts text, CSV, or binary existence and does not inspect database records. | Assert query results through captured variables or stdout, or use CSV/text fixtures. |
| async function semantics | function_state return assertions reject coroutine functions rather than awaiting them. | Teach async syntax through source structure or a separate runtime designed for asynchronous evaluation. |
| exception messages and instance attributes | function_state can assert an exact exception type name but cannot compare the exception message or inspect attributes on the exception object. | Catch the exception in student code and expose its message or selected attributes through stdout or a captured variable. |
